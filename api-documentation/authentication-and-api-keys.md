# Authentication and API Keys

Public reads tested in this audit succeeded without a key. The live OpenAPI declares an optional `apikey` query parameter on many routes. Explorer account support is enabled, but no private account session or key creation was exercised.

Use only keys generated by the TurkScan® account workflow when it is available. An Etherscan key or upstream service key is not automatically a TurkScan key. Operator import APIs and sensitive endpoints can require separate credentials, session state or CSRF protection.

Never publish API credentials in code, screenshots, query examples or this repository. Rate and access policies can vary by route. An optional `key` field in the generated schema is not a public shared secret. See [Rate Limits](rate-limits.md).
